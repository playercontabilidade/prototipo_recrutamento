# Design: Solicitação de Entrevista pelo Gestor

Generated by brainstorming on 2026-09-10  
Repo: Prototipação Vagas (local)  
Status: APPROVED  
Mode: Builder  
Approach: **1** — entidade `interviewRequests[]` + Pendências RH/gestor + criação de `interviews` ao confirmar

## Problem Statement

O gestor precisa **pedir ao RH** uma nova entrevista com um candidato (motivo, tipo, participantes, sugestões de agenda), sem confundir isso com **agendar diretamente**.

Hoje “Solicitar entrevista” no painel do gestor é **stub** (`gestorWantsInterview` + histórico/toast). Agendar completo existe só no fluxo RH (`openInterviewEditor`). A empresa pode configurar se o gestor também pode agendar direto.

## Anti-redundância

| Pergunta | Resposta |
|----------|----------|
| Já existe fluxo com o mesmo JTBD? | Parcial — stub `entrevistar` / `gestorWantsInterview`. **Substituir** stub por solicitação tipada. |
| Cabe em hub existente? | Sim — entrada no `#gestorCandidatePanel`; acompanhamento em Pendências gestor e RH. **Sem** item novo na sidebar. |
| Informação já aparece em outro lugar? | Pendências passam a incluir o tipo; ao `Agendada`, a fonte de verdade da agenda é `interviews`. |
| RH × Gestor mesmo fluxo? | Não. Gestor solicita/confirma/cancela. RH analisa e propõe horário (Pendências RH). |
| KPI/histórico duplicado? | Uma entidade `interviewRequests`; stubs antigos deixam de ser a fonte. |

**Evita:** nova sidebar; embutir `#pendenciasPage` no modo gestor; pré-criar `interviews` no status “Solicitada”; segunda inbox só de entrevistas fora de Pendências.

## Decisions

| Tema | Decisão |
|------|--------|
| Escopo da onda | **B** — loop curto: solicitar → RH propõe → gestor confirma → `Agendada` |
| Entrada gestor | **A** — só `#gestorCandidatePanel` |
| Superfície RH | **A** — `#pendenciasPage` / `buildPendencies()` |
| Abordagem de dados | **1** — `interviewRequests[]` |
| Permissão | **B** — toggle `gestorPodeAgendarEntrevista` (default off); pedir sempre disponível |
| Stub legado | Ação `entrevistar` / `solicitar_entrevista` abre o dialog de solicitação (não só flag+toast) |

## Scope

### In

- Modelo `interviewRequests` + seeds (pelo menos 1 em `RH analisando` e 1 em `Aguardando agenda`)
- Dialog de solicitação no painel do candidato (gestor): motivo, tipo, participantes, sugestões de data/horário, observação; candidato e vaga pré-preenchidos (somente leitura)
- Ações: Solicitar; Cancelar; Acompanhar; Confirmar horário proposto
- Status jogáveis: `Solicitada` → `RH analisando` → `Aguardando agenda` → `Agendada` (+ `Cancelada`)
- RH: pendência tipada + dialog para propor horário ou cancelar
- Gestor: pendências derivadas para acompanhar / confirmar / cancelar
- Ao confirmar: criar registro em `interviews` e vincular `interviewId`
- Toggle demo `gestorPodeAgendarEntrevista` (+ atalho “Agendar entrevista” no painel quando on)
- Cache bump; `graphify update` após código

### Out

- Item novo na sidebar
- UI “Realizada” nesta onda (continua no ciclo normal de entrevistas)
- Inbox RH fora de Pendências / aba dedicada em Entrevistas
- Múltiplas solicitações abertas por candidato+vaga
- Backend / notificações reais
- Formulário de solicitação de **vaga** (`hiringRequests`) — domínio diferente

## Surfaces

1. **Gestor — painel candidato** (`#gestorCandidatePanel`): CTA Solicitar entrevista → dialog; se permissão on, CTA Agendar entrevista → `openInterviewEditor`
2. **Gestor — Pendências** (`homeFilter=analises` / `buildGestorPendencies`): cards da solicitação (acompanhar, confirmar, cancelar)
3. **RH — Pendências** (`#pendenciasPage` / `buildPendencies`): tipo `entrevista_solicitacao_gestor` → propor horário / cancelar
4. **Entrevistas** (`interviews`): só após confirmação (`Agendada`)

## Data model

```text
interviewRequest = {
  id: number | string
  candidateId: number
  jobId: number | null
  vacancy: string
  reason: string
  interviewType: string          // ex.: Técnica, Gestor, RH, Painel
  desiredParticipants: string[]  // nomes ou papéis
  suggestedSlots: [{ date: "YYYY-MM-DD", time?: "HH:mm" }]
  note: string
  status: "Solicitada" | "RH analisando" | "Aguardando agenda" | "Agendada" | "Realizada" | "Cancelada"
  requester: string              // currentManagerName
  createdAt: string
  updatedAt: string
  rhProposedSlot: null | {
    date: "YYYY-MM-DD"
    time: "HH:mm"
    modality?: string
    location?: string
    proposedBy?: string
  }
  interviewId: number | null     // set when Agendada
  cancelReason?: string
}

interviewRequests: interviewRequest[]
```

**Helpers (protótipo):**  
`buildInterviewRequests()` não é necessário se a lista for mutável em memória como `hiringRequests`.  
`openInterviewRequestDialog(candidate)`, `submitInterviewRequest(...)`, `proposeInterviewRequestSlot(req, slot)`, `confirmInterviewRequest(req)`, `cancelInterviewRequest(req, reason?)`.

**Integração Pendências RH:** em `buildPendencies()`, itens com `type: "entrevista_solicitacao_gestor"` para status `Solicitada` | `RH analisando` (assignee RH).  
**Integração Pendências gestor:** em `buildGestorPendencies()`, tipo `gestor_entrevista_solicitacao` para o requester atual conforme status (confirmar quando `Aguardando agenda`).

## Status / ações

| Status | Quem age | Ações |
|--------|----------|--------|
| Solicitada | RH (ou auto → RH analisando no envio) | Propor horário · Cancelar |
| RH analisando | RH | Propor horário · Cancelar |
| Aguardando agenda | Gestor (requester) | **Confirmar horário** · Cancelar · Acompanhar |
| Agendada | — (agenda em `interviews`) | Solicitar some das pendências de ação |
| Cancelada | — | Somente histórico / seed |
| Realizada | Fora desta onda | Ciclo normal de entrevistas |

**Regras**

- Ao **Solicitar**: status inicial `RH analisando` (ou `Solicitada` por um tick e já entra como pendência RH — preferir gravar `RH analisando` no submit para o loop B).
- **Uma** solicitação aberta por `candidateId` + vaga (`Solicitada` | `RH analisando` | `Aguardando agenda`); nova tentativa → toast.
- Cancelar permitido ao gestor e ao RH enquanto não `Agendada` / `Realizada`.
- Confirmar: exige `rhProposedSlot`; cria `interviews` com data/hora/modalidade; `status = Agendada`; `interviewId` preenchido.
- Toggle `gestorPodeAgendarEntrevista === false`: ocultar CTA agendar direto; solicitar permanece.

## UI notes

- Dialog alinhado ao design system (form-field, dialog-actions); candidato e vaga como texto/readonly.
- Sugestões de horário: 1–3 slots (data + hora opcional).
- Cards de pendência no padrão já usado (RH `.pendencias-card` / gestor hub).
- Toggle demo junto aos demais `#gestorPerm*` na home do gestor.
- Empty: sem solicitação aberta relevante → não poluir lista; empty de filtro mantém “Limpar filtro” onde já existe.

## Error / empty states

- Campos obrigatórios (motivo, tipo) vazios → bloqueia submit.
- Já existe pedido aberto → toast, não cria outro.
- Candidato/vaga inexistente ao abrir CTA → toast + fecha.
- Confirmar sem `rhProposedSlot` → não deve aparecer CTA.
- Subject órfão na pendência → toast, não quebra render.

## Testing (manual)

1. Modo Gestor → abrir candidato → Solicitar entrevista → preencher → enviar  
2. Modo RH → Pendências → ver item → Propor horário  
3. Modo Gestor → Pendências → Confirmar horário → entrevista aparece em Entrevistas / status Agendada  
4. Cancelar em `RH analisando` e em `Aguardando agenda`  
5. Segunda solicitação com pedido aberto → bloqueada  
6. Toggle “Pode agendar direto” on → CTA Agendar aparece; off → só Solicitar  
7. Confirmar que stub antigo não é mais o único comportamento de `entrevistar`
