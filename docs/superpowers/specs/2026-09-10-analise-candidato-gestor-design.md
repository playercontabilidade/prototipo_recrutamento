# Design: Análise de Candidatos pelo Gestor

Approach: A — Dialog amplo `#gestorCandidatePanel` (coluna única + mini-dialog de decisão)

## Problem Statement

Quando o candidato chega a uma etapa que exige **análise ou decisão do gestor**, o portal precisa de uma experiência completa: ler perfil e resultados do processo, decidir (entrevistar, avançar, reprovar, pedir avaliação, banco, manter em análise) e registrar histórico — **sem** substituir a ficha de entrevista.

Hoje `#gestorCandidatePanel` existe (spec acompanhamento 2026-09-07) com abas rasas Artefatos | Parecer e ações stub sem formulários. RH tem `managerAnalyses` / Análises de gestores; a decisão do gestor deve continuar no painel do portal, não no dossiê RH.

## Anti-redundância

| Pergunta | Resposta |
|----------|----------|
| Já existe fluxo com o mesmo JTBD? | Sim — `#gestorCandidatePanel`. **Estender**, não criar paralelo. |
| Cabe em hub existente? | Portal do gestor; entrada pela vaga, análises e funil. Sem item novo na sidebar. |
| Informação já aparece em outro lugar? | Scorecard, fit, testes, entrevistas: **só ler** das fontes existentes. |
| RH × Gestor mesmo fluxo? | RH acompanha em Análises; gestor decide no painel. Um parecer de **entrevista** → ficha da entrevista. |
| KPI/histórico duplicado? | Decisões do gestor → `gestorNotes` + timeline da candidatura (uma fonte). |

**Evita:** nova página “Análise” na nav; segundo modal de parecer além do painel; reabrir `#candidateDialog` (dossiê RH) como superfície de decisão.

## Decisions

| Tema | Decisão |
|------|--------|
| Superfície | **1** — Dialog amplo `#gestorCandidatePanel` |
| Layout interno | **A** — Coluna única: header → perfil → resumo → histórico → footer ações |
| Formulários de ação | Mini-dialog `#gestorCandidateDecisionDialog` (padrão solicitações) |
| Reprovação | Flag `gestorPodeReprovarDireto` (já existente) |
| Pretensão / faixa | Flag `gestorVeFaixaSalarial` |
| Parecer de entrevista | Fora desta tela — permanece na ficha da entrevista |
| Abordagem | Estender painel + seeds ricos + cache bump |

## Scope

### In

- Header rico: candidato, vaga, etapa, tempo no processo, tags, score geral, responsável
- Seção Currículo e perfil (leitura): currículo, experiências, formação, competências, conhecimentos, disponibilidade, pretensão se permitido
- Seção Resumo do processo (leitura): triagem RH, entrevistas + pareceres resumidos, teste técnico, comportamental, Fit Cultural, avaliação por competências, Scorecard, score geral
- Seis ações com formulário: Quero entrevistar · Recomendar avanço · Recomendar reprovação · Solicitar avaliação adicional · Banco de Talentos · Manter em análise
- Histórico de decisões (gestor, ação, data/hora, justificativa, etapa)
- Integração leve com pendências (agendamento / avaliação adicional) via stub/regra existente quando couber
- Entradas: tabela da vaga, card análises do gestor, `openGestorAnalysis`
- Remover/simplificar abas Artefatos \| Parecer em favor do scroll único (ou manter aba só se necessário para acessibilidade — preferência: **sem abas**, scroll único)
- Seeds de candidato(s) com artefatos preenchidos para demo
- Cache bump

### Out

- Novo item de sidebar / página RH dedicada
- Usar `#candidateDialog` como superfície de decisão
- Condução/preenchimento da ficha de entrevista nesta tela
- PDF/e-mail reais; backend/auth
- Contratação automática a partir de recomendação de avanço
- Mover stage sozinho em “Recomendar avanço” (só recomenda)

## Surfaces

1. `#gestorCandidatePanel` — dialog principal (conteúdo de leitura + histórico + footer)
2. `#gestorCandidateDecisionDialog` — formulário por tipo de ação
3. Entradas existentes no `#gestorPage` (sem nav nova)

## Data model

```text
# Reuso
companyGestorPermissions.{ gestorPodeReprovarDireto, gestorVeFaixaSalarial }
managerAnalyses[]          # banner / deep-link
candidate.gestorNotes[]    # histórico de decisões do gestor
candidate.history / timeline

# Decisão (payload do mini-dialog → note tipada)
gestorDecision = {
  action: "entrevistar" | "avancar" | "reprovar" | "avaliacao_adicional" | "banco" | "manter"
  at, by, stageAtDecision
  justification / observation
  // por ação:
  nextStage?               // avancar
  rejectReason?            // reprovar
  evaluationType?          // tecnico | comportamental | fit | outra
  talentArea?              // banco
}

# Pendência stub (quando aplicável)
// entrevistar → tipo agendamento
// avaliacao_adicional → tipo avaliação
```

Derivar tempo no processo / tags / score / responsável dos campos já usados no portal gestor e no candidato (sem segunda entidade).

## Status / efeitos das ações

| Ação | Campos obrigatórios | Efeito |
|------|---------------------|--------|
| Quero entrevistar | obs. opcional | `gestorNotes` + pendência de agendamento (stub) + toast |
| Recomendar avanço | próxima etapa + justificativa | nota; **não** altera stage |
| Recomendar reprovação | motivo + justificativa | nota; se flag on → reprova de fato (como hoje) |
| Avaliação adicional | tipo + motivo (+ obs.) | nota + pendência stub RH |
| Banco de Talentos | motivo + área/cargo (+ obs.) | nota; não remove sozinho do processo |
| Manter em análise | observação | nota; fecha painel |

Cada ação grava: gestor, ação, data/hora, justificativa, etapa atual.

## UI notes

- Header compacto com chips (etapa, tags, score)
- Perfil em grade de fatos (`gestor-request-fact` / padrões do portal)
- Resumo do processo em lista de resultados (rótulo + valor/resumo + estado vazio “Não aplicado” / “Pendente”)
- Histórico cronológico abaixo
- Footer sticky ou fixo no dialog: botões secundários + primário contextual se houver análise pendente
- Mini-dialog: título da ação, campos, Cancelar / Confirmar
- Visual: design system existente (brand verde); sem tema novo
- Toggle demo das flags permanece no painel Demo do gestor

## Error / empty states

- Candidato sem artefato → “Não aplicado” / “Pendente” no item
- Ação sem campos obrigatórios → bloqueia submit + toast
- Análise sem candidato ligado → toast (já existe em `openGestorAnalysis`)
- Pretensão oculta se `gestorVeFaixaSalarial === false`

## Testing (manual)

1. Portal Gestor → vaga → abrir candidato → ver header/perfil/resumo  
2. Abrir a partir de Análises pendentes  
3. Cada uma das 6 ações com formulário e entrada no histórico  
4. Reprovação com flag off (só recomenda) e on (reprova)  
5. Pretensão visível/oculta conforme flag  
6. Confirmar que não abre ficha de entrevista nem dossiê RH como decisão  
7. “Quero entrevistar” gera pendência visível no hub (se regra existir) ou toast + nota
