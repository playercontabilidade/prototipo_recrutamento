# Design: Pendências (inbox de ação RH / equipe)

Generated by brainstorming on 2026-09-04

Approach: 1 — Página `#pendenciasPage` + `buildPendencies()` derivado + ações rápidas nos fluxos existentes

## Problem Statement

O protótipo precisa **mostrar claramente tudo que precisa de ação** do RH, gestor ou entrevistador: separar Minhas / Equipe / Vencidas / Próximas do vencimento; tipar a natureza da pendência; e oferecer ações rápidas (analisar, avaliar, abrir entrevista, aprovar/reprovar, etc.).

Hoje existem filtros de pendência/SLA no Pipeline, textos no Dashboard/topbar e “análises pendentes” no Portal do gestor, mas **não há hub unificado** tipado com buckets e CTAs.

## Decisions

| Tema | Decisão |
|------|--------|
| Onde mora | **A** — página própria **Pendências** na nav |
| “Minhas” | **A** — sessão RH fixa (`Larissa Dias`); Equipe = demais assignees |
| Origem dos itens | **A** — derivados por regras + seeds para cobertura de tipos |
| Profundidade MVP | **A** — 4 buckets · 10 tipos · ações rápidas nos fluxos existentes |
| Abordagem | **1** — `buildPendencies()` + página hub |
| Persistência | Em memória; “resolver” = navegar ao artefato (+ toast); sem fila manual obrigatória |
| Pipeline | Coexiste; não é substituído |

## Scope

### In

- Nav **Pendências** com contagem (Minhas + vencidas, ou total de Minhas)
- `#pendenciasPage`: abas Minhas · Equipe · Vencidas · Próximas do vencimento
- Filtro por tipo (chips)
- Cards: tipo, sujeito (candidato/vaga), responsável, prazo, urgência, CTAs
- `buildPendencies()` mapeando os 10 tipos a partir de candidatos, jobs, entrevistas, score, propostas, SLA, talentos
- Ações: Analisar/Abrir candidatura · Preencher avaliação · Abrir entrevista · Aprovar/Reprovar · Enviar retorno · Reagendar · Resolver (navega + toast)
- Seeds suficientes para demonstrar cada tipo e cada bucket
- Cache bump
- Atalho leve no topbar/dashboard (opcional se couber sem inflar escopo — **incluir contagem no nav; topbar opcional**)

### Out

- Seletor de persona / três inboxes na nav
- Fila `pendingItems[]` como fonte principal
- Push/e-mail reais
- Backend
- Remover filtros de pendência do Pipeline

## Surfaces

1. Nav `data-page="pendencias"` → `#pendenciasPage`
2. Abas/buckets + filtro de tipo
3. Lista de cards + empty states
4. Deep-links para dossiê, entrevista, score, dispensa/banco, comunicação stub

## Data model

```text
CURRENT_RH_USER = "Larissa Dias"

PENDING_TYPES =
  curriculo | entrevista_resultado | ficha | avaliacao |
  parado | sla | vaga_aprovacao | proposta_aprovacao |
  retorno | banco_revisao

pendingItem:
  id: string
  type: PENDING_TYPES
  title: string
  description: string
  assignee: string
  dueAt: string | null          // ISO
  createdAt?: string
  subject: { kind: candidate|job|interview|score|talent|..., id: number|string }
  primaryAction: string         // action id
  secondaryActions: string[]
  // computed views:
  // mine = assignee === CURRENT_RH_USER (ou assignee vazio tratado como RH)
  // team = !mine
  // overdue = dueAt < hoje OR type===sla with overdue
  // dueSoon = dueAt within 3 days and not overdue
```

### Derivação (regras MVP)

| type | Regra aproximada |
|------|------------------|
| curriculo | candidato em Triagem com alerta/histórico “aguardando” ou seed |
| entrevista_resultado | interview status Realizada / aguardando resultado sem draft finalizado |
| ficha | condução com pendências / seed |
| avaliacao | scoreEvaluation Pendente \| Parcial \| Em revisão |
| parado | daysInStage alto ou nextActionAt vencido |
| sla | slaStatus(candidate).overdue |
| vaga_aprovacao | job.status aguardando aprovação (seed se status não existir) |
| proposta_aprovacao | proposal status enviada / aguardando |
| retorno | “aguardando retorno” em history/tags ou proposta enviada ao candidato |
| banco_revisao | talent status bloqueados ou seed “aguardando revisão” |

Detalhes exatos de campos: confirmar no `app.js` na implementação (`slaStatus`, statuses de job/proposal/interview).

## Buckets (vistas)

- **Minhas** — `assignee === CURRENT_RH_USER`
- **Equipe** — demais
- **Vencidas** — overdue (todos os assignees)
- **Próximas do vencimento** — dueSoon (todos)

Um item pode aparecer em Minhas e também ser overdue; nas abas Vencidas/Próximas entra independente de Minhas/Equipe.

## UI notes

- Contagens nas 4 abas
- Chip **Todos** + tipos presentes na vista atual
- Card: badge de tipo · prazo (vencido / em X dias) · responsável · primária + secundárias
- Empty: “Nada por aqui” + limpar filtro se aplicável

## Ações rápidas

| action id | Comportamento |
|-----------|----------------|
| analisar / abrir_candidatura | `openCandidate(id)` |
| preencher_avaliacao | open/create score evaluation |
| abrir_entrevista | `openInterviewDetail(item)` |
| aprovar | banco / fluxo positivo existente |
| reprovar | `dismissCandidate` / diálogo |
| enviar_retorno | comunicação ou toast stub |
| reagendar | detalhe entrevista + fluxo reagendar |
| resolver | toast + navega ao subject (não inventar store de “done” salvo se trivial em sessão) |

## Error / empty states

- Bucket vazio → empty state
- Subject sumiu → toast “Registro não encontrado”
- Tipo sem regra real no código → cobrir com seed explícito documentado

## Testing (manual)

1. Nav Pendências → 4 abas com contagens
2. Ver tipos variados nos seeds
3. Filtrar por tipo
4. CTA abre dossiê / entrevista / score
5. Item SLA aparece em Vencidas
6. Item dueSoon em Próximas
7. Minhas mostra assignee Larissa; Equipe mostra outros
