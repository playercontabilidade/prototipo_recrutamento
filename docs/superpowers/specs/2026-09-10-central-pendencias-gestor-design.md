# Design: Central de Pendências do Gestor

Generated by brainstorming on 2026-09-10  
Repo: Prototipação Vagas (local)  
Status: APPROVED  
Mode: Builder  
Approach: A — `buildGestorPendencies()` derivado + lista no Portal do gestor (nav Pendências)

## Problem Statement

O gestor precisa de **uma central** que reúna tudo que depende da ação dele no recrutamento (análises, entrevistas/fichas, solicitações, SLA, proposta quando couber), sem criar solicitações novas e sem misturar com o hub RH.

Hoje a nav **Pendências** do Portal do gestor só lista `managerAnalyses`. A home já espalha “Aguardando sua ação”, KPIs e entrevistas. RH tem `#pendenciasPage` + `buildPendencies()` — JTBD e CTAs diferentes (dossiê RH).

## Anti-redundância

| Pergunta | Resposta |
|----------|----------|
| Já existe fluxo com o mesmo JTBD? | Parcial — home + nav fraca. **Estender** nav Pendências do gestor. |
| Cabe em hub existente? | Sim — `#gestorPage` / `homeFilter=analises` / `#gestor-pendencias`. **Sem** item novo na sidebar. |
| Informação já aparece em outro lugar? | Contagens na home passam a ler a mesma fonte (`buildGestorPendencies`). |
| RH × Gestor mesmo fluxo? | Não. RH → `#pendenciasPage`. Gestor → central no portal; CTAs abrem painel/entrevista/solicitação. |
| KPI/histórico duplicado? | Uma função derivada; home e central só leem. |

**Evita:** segunda página tipo RH; reusar `#pendenciasPage` no modo gestor; inbox paralela só de análises.

## Decisions

| Tema | Decisão |
|------|--------|
| Superfície | **1** — Estender Pendências do Portal do gestor |
| Abordagem | **A** — `buildGestorPendencies()` + UI no `#gestorPage` |
| Persistência | Derivada (como RH); some ao concluir na origem |
| Criar solicitações | **Não** — só agrega |
| Parecer de entrevista | Continua na ficha; aqui só CTA “Continuar ficha” |

## Scope

### In

- Substituir a lista só-de-análises em Pendências do gestor por hub tipado
- Resumo: Atrasadas · Para hoje · Próximas · Total (+ linha de exemplos clicável)
- Tipos: candidatos (análise, decisão, avaliação adicional); entrevistas (próxima, sem ficha, parecer); vagas (aprovação, ajuste); outras (proposta se gestor, SLA)
- Card: tipo, candidato/vaga, origem, criação, prazo, prioridade, status
- Prioridade visual: Vencida | Hoje | Próxima | Normal
- Ações rápidas deep-link (analisar, abrir entrevista, continuar ficha, abrir/corrigir solicitação, aprovar/reprovar na origem, abrir vaga)
- Filtros por bucket + grupo de tipo
- Home/KPI apontando para a mesma fonte
- Seeds suficientes para demo dos tipos
- Cache bump

### Out

- Novo item de sidebar
- Embutir `#pendenciasPage` no modo gestor
- Criar/editar solicitações nesta tela
- “Marcar como concluída” manual
- Backend / notificações reais

## Surfaces

1. `#gestorPage` vista Pendências (`homeFilter === "analises"`) — resumo + filtros + lista
2. CTAs → `#gestorCandidatePanel`, detalhe entrevista/ficha, solicitação (inbox aprovação/ajuste), vaga
3. Home do gestor — métricas/atalhos leem `buildGestorPendencies` (sem segundo modelo)

## Data model

```text
gestorPendingItem = {
  id: string                    // estável p/ dedupe
  type: gestorPendingType
  group: "candidatos" | "entrevistas" | "vagas" | "outras"
  title: string
  subjectLabel: string          // candidato ou vaga
  origin: string
  createdAt: date
  dueAt: date | null
  priority: "overdue" | "today" | "soon" | "normal"
  status: string
  primaryAction: string
  secondaryActions?: string[]
  subject: { kind, id }
}

buildGestorPendencies() → gestorPendingItem[]
  // escopo: currentManagerName (+ approvalPersona quando tipo = aprovação de solicitação)
  // fontes: managerAnalyses, interviews/fichas, hiringRequests (aprovação/ajuste),
  //         propostas se gestor, SLA candidatos/vagas do gestor, flags gestorExtraEvaluation etc.
```

Mapeamento de CTAs (exemplos):  
`analisar_candidato` → painel análise · `abrir_entrevista` / `continuar_ficha` → entrevista · `abrir_solicitacao` / `corrigir_solicitacao` → formulário solicitação · `abrir_vaga` → detalhe vaga.

## Prioridade

| Prioridade | Critério (protótipo) |
|------------|----------------------|
| Vencida | `dueAt < TODAY` ou tipo SLA estourado |
| Hoje | `dueAt === TODAY` ou entrevista no dia |
| Próxima | dentro de N dias (ex. 3) |
| Normal | demais |

## Auto-conclusão

Itens são **recomputados** a cada render. Exemplos:

- Análise: some quando `managerAnalyses` deixa de estar `pending` / parecer registrado  
- Ficha: some quando entrevista `Realizada` e ficha/parecer concluídos  
- Solicitação: some quando sai de “Aguardando aprovação” / “Ajuste solicitado” para o papel atual  
- Avaliação adicional: some quando flag/`gestorExtraEvaluation` resolvida ou retorno registrado  

## UI notes

- Layout alinhado ao Portal do gestor (cards, chips de prioridade, filtros)
- Resumo em faixa de 4 métricas + exemplos
- Lista densa com badge de prioridade e CTA primário
- Empty state: “Nada pendente para você.”
- Contagem no nav = Total (ou Atrasadas + Hoje, se preferível no implemento — default **Total**)

## Error / empty states

- Sem itens no filtro → empty com sugestão de limpar filtro  
- Subject sem registro → toast + não quebra lista
