# Design: Onda 1 — vagas, status, contratação e portal

## Problem Statement

O protótipo precisa servir de **spec viva** para o desenvolvimento real: RH, produto/eng e candidato têm de ver o mesmo modelo. O modal de vaga estava carregado de botões; cancelar / reabrir / arquivar e a contratação na pipeline não reagiam de forma previsível na aba Vagas nem no portal (hoje o portal lista Pausadas e o CTA só desliga se a pessoa já se candidatou).

## What Makes This Cool

O “whoa” é um fio único: gerir a vaga → contratar no pipeline → listagem RH e portal reagem na hora (posições, status, porta de candidatura fechada).

## Constraints

- Demo estruturada para o desenvolvimento real (não descartável).
- Audiência: RH + produto/eng + candidatos (portal).
- Entrega por ondas. Este spec é **somente a Onda 1**.
- Portal = reação (lista, detalhe, CTA). Sem redesign de “minhas candidaturas”.
- Sem telas novas. Reusar `#jobDetailDialog`, `#jobStatusDialog`, pipeline e views públicas.
- Front estático: `index.html`, `app.js`, `styles.css`.

## Premises

1. Três helpers separam conceitos que não são equivalentes:
   - `jobIsVisibleInPortal(job)`: define presença na vitrine pública.
   - `jobAcceptsApplications(job)`: define candidatura externa.
   - `jobCanHire(job)`: define se o RH pode concluir uma contratação já iniciada.
2. **Arquivada não é status.** É `job.archived: boolean`. O `status` permanece (Aberta, Pausada, Encerrada, Cancelada, …). Desarquivar só liga `archived = false`; o status não muda.
3. Preenchidas derivam de Contratados. Preferir `jobId`; fallback `vacancy === job.title` nos seeds antigos.
4. Campo **motivo** obrigatório só em cancelar e reprovar (campo visível). Nos outros fluxos o campo motivo fica **oculto**. **Observação** sempre opcional e visível.
5. Aviso em “minhas candidaturas” já enviadas é **Onda 2 — não implementar nesta onda**.

## Vocabulário (não misturar)

- **Pilares da Onda 1:** modal limpo + máquina de status + contratação ao vivo + portal reagindo.
- **Roteiro de demo (3 atos):** (1) modal RH, (2) contratar até N/N, (3) portal bloqueia. É o critério de aceite, não um corte de escopo extra.
- As Approaches A–D abaixo são alternativas de **escopo de entrega**, já decididas.

## Approaches Considered

### Approach A: Só lado RH

Rejeitada: audiência inclui candidatos.

### Approach B: Slice RH + pipeline + portal-reação

**Escolhida como corte de escopo da Onda 1.** O roteiro de 3 atos é como demonstramos esse corte.

Rejeitada: empurra status e aba Vagas.

### Approach D: App inteiro agora

Rejeitada como implementação única. Vira backlog de ondas (Onda 2+).

## Modelo

```
job.archived: boolean          // default false
job.status: "Rascunho" | "Aguardando aprovação" | "Aberta" | "Pausada" | "Encerrada" | "Cancelada"
job.openings: number >= 1
job.id: number                 // chave estável
```

Vitrine do portal (`jobIsVisibleInPortal` / `publicJobs`):

```
status ∈ {Aberta, Pausada} AND archived === false
```

Arquivar uma Aberta/Pausada tira da vitrine mesmo com status inalterado. Desarquivar uma Aberta com vaga restante devolve à vitrine.

## Seção 1 — Elegibilidade e status

`jobIsVisibleInPortal(job)` é true somente se:

- `archived === false`
- `status ∈ {"Aberta", "Pausada"}`

`jobAcceptsApplications(job)` é true somente se:

- `jobIsVisibleInPortal(job) === true`
- `status === "Aberta"`
- `jobRemainingCount(job) > 0`

`jobCanHire(job)` é true somente se:

- `archived === false`
- `status ∈ {"Aberta", "Pausada"}`
- `jobRemainingCount(job) > 0`

A separação é intencional: pausar fecha a entrada de novos candidatos, mas não impede o RH de concluir uma contratação que já estava em andamento.

| Status (se `archived`) | Lista RH | Vitrine portal | Candidatar-se | Overflow típico (Processo/Desfecho) |
|------------------------|----------|----------------|---------------|-------------------------------------|
| Rascunho | sim | não | não | enviar aprovação, publicar |
| Aguardando aprovação | sim | não | não | aprovar, reprovar |
| Aberta (restantes > 0) | sim | sim | sim | pausar, encerrar, cancelar |
| Aberta (restantes = 0) | sim | sim | não | encerrar, cancelar |
| Pausada | sim | sim | não | reabrir, encerrar, cancelar |
| Encerrada | sim | não | não | reabrir, arquivar |
| Cancelada | sim | não | não | arquivar (sem reabrir) |
| qualquer + `archived` | só “Mostrar arquivadas” | não | não | desarquivar (primária) |

Confirmações:

- Cancelar / reprovar: motivo visível e obrigatório; confirmar com classe de perigo.
- Pausar / reabrir / encerrar / arquivar: motivo oculto; observação opcional.
- Pausar / reabrir / encerrar: modal de detalhes permanece aberto e atualiza.
- Cancelar / arquivar: fecham o modal de detalhes.

## Seção 2 — Modal RH

Quadro operacional, não grid de 11 botões. Ordem: cabeçalho → posições + barra → alerta (só Aberta e restantes = 0) → toolbar → resumo / contratados / ajustar posições → histórico.

Ajustar posições: oculto se Encerrada, Cancelada **ou** `archived`.

### Primárias (toolbar)

| Condição | Primárias |
|----------|-----------|
| `archived` | Desarquivar · Ver histórico |
| Aberta | Candidatos · Editar · Compartilhar |
| Pausada | Candidatos · Editar · Compartilhar |
| Rascunho | Candidatos · Editar |
| Aguardando aprovação | Candidatos · Editar |
| Encerrada | Candidatos · Compartilhar · Contratados |
| Cancelada | Candidatos |

### Overflow (Mais ações) — keep da gestão já existente

Além do Processo/Desfecho da tabela da Seção 1, manter no grupo Gestão quando já existia: Duplicar; em Aberta também Adicionar candidato, Banco de Talentos, Ver contratados. Não inventar ações novas nesta onda.

Compartilhar: no-op demonstrativo (copia URL). Não precisa rotear o hash `#vaga-${id}` nesta onda.

Scroll só em Resumo + Histórico. Toolbar/menu não recortam. Clique no card da listagem abre o modal (não navega de página).

## Seção 3 — Dados, contratação e portal

### Preenchidas

```
jobHiredCandidates(job) =
  results where status === "contratados"
  and (item.jobId === job.id  OR  (item.jobId == null && item.vacancy === job.title))
```

`hireCandidate` grava `jobId: job.id` no resultado novo. Seeds sem `jobId` continuam no fallback por título.

Renomear: atualiza `job.title` e, nos itens **sem** `jobId` ligados por título antigo, atualiza `vacancy` para não órfãos. Itens com `jobId` não dependem do título para filled. `openings` não pode ficar < filled.

Candidatos na listagem RH: seed de demo, decrementado quando alguém sai do pipeline. Não zerar pelo tamanho do kanban.

### Contratar (pipeline)

Permitido somente quando `jobCanHire(job)` é true. Encerrada / Cancelada / archived ou sem posições: toast e não contrata.

1. Exige proposta cadastrada.
2. Se o e-mail já está em Contratados desta vaga, não duplica o result; ainda assim remove do pipeline se estiver lá.
3. Remove do kanban. **Não chamar `goToPage`.** O card some; a pessoa continua na página pipeline.
4. Histórico da vaga: `{nome} contratado · {filled}/{openings}`.
5. Se restantes = 0 e status Aberta: toast + alerta no modal (se aberto).

### Portal — precedência da mensagem (lista e detalhe)

Primeira regra que casar, de cima para baixo:

1. Já se candidatou a esta vaga → copy do botão “Já candidatado”; sem a frase de pausada/esgotada.
2. Pausada (e não archived) → “Esta vaga está temporariamente pausada.”
3. Restantes = 0 → “Todas as posições desta vaga já foram preenchidas.”

Badge na **lista e no detalhe** quando a regra 2 ou 3 aplica (não no caso 1). Texto do badge: `Pausada` ou `Vagas preenchidas`.

### Matriz do CTA (detalhe)

| `jobAcceptsApplications` | Já candidatado | Botão |
|--------------------------|----------------|--------|
| true | não | “Candidatar-se”, enabled |
| true | sim | “Já candidatado”, disabled |
| false | não | “Candidatar-se”, disabled + copy 2 ou 3 |
| false | sim | “Já candidatado”, disabled (regra 1) |

### Call sites dos helpers (lista fechada)

- `jobIsVisibleInPortal`: `publicJobs` e validação do detalhe público.
- `jobAcceptsApplications`: checkbox/seleção de bulk na lista pública, CTA do detalhe, `openCandidateApplyView`, `openCandidateBulkApplyView` e `submitCandidateApplication`.
- `jobCanHire`: `hireCandidate`.

`submitCandidateApplication` deve **revalidar** a elegibilidade, pois o RH pode pausar ou encerrar a vaga com o formulário de candidatura já aberto.

### Detalhe órfão

Se `selectedPublicJobId` aponta para vaga fora da vitrine (encerrada, cancelada, archived, rascunho): não substituir por `publicJobs()[0]`. Voltar à lista de vagas com toast curto (“Esta vaga não está mais disponível.”).

## Success Criteria

Aceite = os 3 atos **manuais** no mesmo reload (sem suite automatizada):

1. **Ato 1 — modal:** abrir vaga Aberta; primárias da tabela; Mais ações só com pausar/encerrar/cancelar + gestão keep.
2. **Ato 2 — contratar:** contratar até filled = openings; listagem N/N; histórico; alerta encerrar; permanece em pipeline (sem ir para Resultados).
3. **Ato 3 — portal:** a mesma vaga Aberta com 0 restantes (ou uma Pausada) na vitrine, badge + CTA disabled + copy; Encerrada / Cancelada / archived **fora** da lista.

Também no mesmo pacote (smoke, não ato de palco): cancelar pede motivo e some da vitrine; reabrir Pausada/Encerrada → Aberta; se restantes > 0 o CTA do portal volta.

Rascunho / aprovação / publicar / reprovar: não quebram; **não** são critério desta onda.
