## Problem Statement

Depois que a solicitação vira vaga, o gestor precisa **acompanhar o andamento da seleção**: resumo da vaga, funil, candidatos e informações do pedido — sem misturar com a decisão final do candidato. A decisão ocorre na **análise do candidato** (painel do gestor). Recomendar reprovação não implica reprovar direto; depende de permissão/config da empresa.

## Decisions

| Tema | Decisão |
|------|--------|
| Onde mora | Portal do Gestor (`#gestorPage`) |
| Navegação | Home → detalhe full-page da vaga → Voltar |
| Organização | Abas **Andamento** \| **Sobre a vaga** |
| Análise / decisão | Painel novo `#gestorCandidatePanel` (não usa dossiê RH `#candidateDialog`) |
| Reprovação | Flag `gestorPodeReprovarDireto` (recomendação vs reprova de fato) |
| Faixa salarial | Flag `gestorVeFaixaSalarial` |
| Abordagem | 1 — detalhe + painel completo nesta onda |

## Scope

### In

- Vista `home` / `job` em `#gestorPage`
- Resumo da vaga (cargo, posições, preenchidas, restantes, abertura, dias em aberto, recrutador, status, SLA)
- Funil resumido com filtro da tabela ao clicar na etapa
- Tabela de candidatos (colunas do brief)
- Ações do gestor conforme permissão (abrir, ver artefatos, comentar, solicitar entrevista, avaliar/parecer, recomendar avanço/reprovação/banco)
- Aba Sobre a vaga (perfil, requisitos, competências, faixa se permitido, etapas, responsáveis, histórico)
- Seed `companyGestorPermissions` + seeds de vaga/candidatos ricos o suficiente para demo
- Deep-link: card “Minhas vagas” → detalhe; filtro de funil na URL/state opcional em memória
- Cache bump

### Out

- Hub novo no RH / nav RH dedicada
- Usar `#candidateDialog` como superfície de decisão do gestor
- PDF/e-mail/WhatsApp reais
- Backend / auth real
- Config UI completa de permissões (só seed/toggle de demo)
- Contratação automática a partir de recomendação

## Surfaces

1. `#gestorPage` vista **home** — stats + Minhas vagas + análises + candidatos (existente; card de vaga abre detalhe)
2. `#gestorPage` vista **job** — header Voltar · abas Andamento | Sobre
3. `#gestorCandidatePanel` — dialog de análise do gestor (artefatos leitura + parecer/recomendações)
4. Preview de currículo stub (reusar padrão existente de resume/PDF stub quando houver)

## Data model

```text
companyGestorPermissions = {
  gestorPodeReprovarDireto: boolean  // default false
  gestorVeFaixaSalarial: boolean     // default true
}

job (campos usados / derivados):
  title, openings, status, openedAt|createdAt, manager, requester, recruiter?
  salaryMin, salaryMax
  slaTargetDays?: number             // default 30
  profile?, requirements?, skills?/competencies?
  processSteps? | stages
  history?: [{ at, label, note? }]

SLA label:
  diasEmAberto = TODAY_KEY - openedAt
  no prazo | em atenção | atrasado  // thresholds vs slaTargetDays (ex. <80%, <100%, >=100%)

Funil (contagens por etapa amigável, mapeada a candidate.stage / pipeline):
  inscritos → triados → entrevistas RH → aguardando gestor → finalistas → contratados

candidate row (derivado):
  name, stage, score, daysInStage, fitCultural summary, technicalTest summary,
  rhEvaluation summary, status, pendencies count/labels
  resumeAvailable: boolean
```

**Minhas vagas (gestor):** vagas em que `job.manager === currentManagerName` **ou** `job.requester === currentManagerName` (união).

## Status / ações

### Recomendações

- `recomendar_avanco` | `recomendar_reprovacao` | `recomendar_banco` → gravam em histórico/parecer do candidato; toast de confirmação; **não** avançam stage sozinhas (exceto ver flag abaixo).

### Reprovação

- Se `gestorPodeReprovarDireto === false`: só recomendação.
- Se `true`: além da recomendação, aplica reprovação no status/stage do candidato (mesmo efeito que RH reprovar no protótipo).

### Parecer / comentário

- Texto obrigatório para “Dar parecer” / Avaliar.
- Comentário livre vai ao histórico da candidatura visível no painel.

### Solicitar entrevista

- Stub nesta onda: grava pedido no histórico da candidatura + toast “Solicitação de entrevista enviada ao RH” (não abre o agendador RH completo).

## UI notes

- **Andamento:** bloco resumo (métricas) → funil (chips/steps) → tabela responsiva com menu de ações por linha.
- **Sobre:** seções empilhadas; faixa salarial ocultável.
- **Painel:** header (nome · vaga · etapa) · abas Artefatos | Parecer · footer ações primárias.
- Visual: padrões do design system (portais / form-field / dialog-actions); sem inventar tema novo.
- Toggle de demo das duas flags: bloco discreto no rodapé da **home** do gestor (só protótipo).

## Error / empty states

- Sem candidatos (ou filtro de etapa vazio) → empty state na tabela.
- Vaga inexistente / sem acesso → toast + volta à home.
- Parecer sem texto → bloqueia submit.
- Ação sem permissão → ocultar ou disabled + tooltip.

## Testing (manual)

1. Portal Gestor → Minhas vagas → abrir detalhe  
2. Resumo e SLA coerentes com seed  
3. Funil filtra tabela  
4. Abrir candidato → ver artefatos → parecer  
5. Recomendar reprovação com flag off (só recomenda) e on (reprova)  
6. Aba Sobre: faixa visível/oculta conforme flag  
7. Voltar à home
