# Design: Timeline da candidatura (dossiê)

Generated by brainstorming on 2026-09-04  
Repo: Prototipação Vagas (local)  
Status: APPROVED  
Mode: Builder  
Approach: 1 — `buildCandidateTimeline(candidate)` no dossiê (aba Histórico → Timeline) + `pushTimelineEvent` + deep-links

## Problem Statement

O protótipo precisa **apresentar de forma clara tudo que ocorreu com a candidatura**: entrada, etapas, entrevistas (incl. reagendamento/ausência), testes, Fit Cultural, avaliações/score, comentários, comunicações, proposta, rejeição, desistência, contratação e banco de talentos — com tipo, data/hora, responsável, descrição, etapa anterior/nova e motivo quando couber.

Hoje o dossiê tem **Histórico** baseado em `history`/`activities` genéricos e o portal tem um stub `candidateApplicationTimeline()`. Não há modelo tipado unificado, filtro por evento nem deep-links para abrir o artefato relacionado.

## Decisions

| Tema | Decisão |
|------|--------|
| Onde mora | **A** — substituir aba **Histórico** do dossiê por Timeline |
| Fontes | **A** — híbrido: agregar módulos existentes + log tipado `timeline[]` |
| Profundidade MVP | **A** — filtro · expandir · deep-links · seeds ricos · hooks RH |
| Abordagem | **1** — `buildCandidateTimeline` + `pushTimelineEvent` |
| Persistência | Em memória no protótipo |
| Portal candidato | Fora desta onda (builder reutilizável depois) |

## Scope

### In

- Renomear rótulo da aba para **Timeline** (manter `data-candidate-tab="history"` / painel `history` por compatibilidade, ou alias `timeline` se trivial)
- UI: filtro por tipo · lista cronológica (mais recente no topo) · expandir detalhes · CTAs
- Modelo de evento normalizado + labels PT dos tipos
- `buildCandidateTimeline(candidate)` agregando:
  - `candidate.timeline[]` (logged)
  - entrevistas (agendada, reagendada, ausência, realizada)
  - testes aplicados, fit assignments, score evaluations
  - proposta / rejeição / desistência / contratação / banco quando dados existirem
  - `history` + `activities` legado mapeados para tipos próximos
- `pushTimelineEvent(candidate, partial)` nas ações RH principais (mover etapa, comentar, rejeitar, desistir, contratar, banco, agendar/reagendar quando o fluxo já existir)
- Deep-links: `interview` · `test` · `fit` · `score` · `message` · `file`
- Seeds: ≥1 candidato com cobertura ampla de tipos
- Cache bump

### Out

- Nav / página Timeline global
- Portal candidato nesta onda
- Auditoria imutável, export PDF, busca full-text avançada
- Backend / persistência real

## Surfaces

1. Dossiê — aba Timeline (`#candidateHistory` host ou substituto tipado)
2. Filtro de tipos (chips ou select)
3. Cards de evento (resumo + painel expandido)
4. Deep-links para modais/fluxos já existentes

## Data model

```text
TIMELINE_TYPES =
  entrada | etapa | entrevista | reagendamento | ausencia |
  teste | fit | avaliacao | comentario | comunicacao |
  proposta | rejeicao | desistencia | contratacao | banco

timelineEvent:
  id: string | number
  type: TIMELINE_TYPES
  at: ISO datetime string
  actor: string                 // responsável
  title: string
  description: string
  fromStage?: string | null
  toStage?: string | null
  reason?: string | null
  related?: { kind: interview|test|fit|score|message|file, id: number|string } | null
  attachments?: { name: string, url?: string }[]
  source: derived | logged

candidate.timeline?: timelineEvent[]   // log tipado (opcional; seeds + push)
```

### Agregação

- `buildCandidateTimeline(candidate)` → array normalizado, sort `at` desc, dedupe leve por `related.kind+id+type` quando fizer sentido (evitar triplicar o mesmo teste).
- Eventos `derived` não precisam estar em `candidate.timeline`.
- Eventos `logged` via `pushTimelineEvent` têm `source: "logged"`.

## UI notes

- Chip **Todos** + um chip por tipo que tenha ≥1 evento (ou lista fixa dos tipos do produto)
- Card colapsado: tipo · at formatado · actor · title/description curta · seta expandir
- Expandido: from/to stage, reason, attachments, CTAs
- Empty state: “Nenhum evento neste filtro”
- Comentários do dossiê continuam na aba Comentários; também geram/aparecem como evento `comentario` na Timeline

## Deep-links

| related.kind | Comportamento |
|--------------|---------------|
| interview | Abrir detalhe da entrevista (`openInterviewDetail` / equivalente) |
| test | `openCandidateTestDetail` |
| fit | `openFitAssignmentDetail` |
| score | `openScoreEvaluationDetail` |
| message | Abrir fluxo de comunicação ou toast se stub |
| file | Toast / preview mock do anexo |

## Error / empty states

- Candidato sem eventos → empty + texto orientando
- Filtro sem matches → empty do filtro + limpar filtro
- Deep-link sem id válido → toast “Registro não encontrado”

## Testing (manual)

1. Abrir dossiê seed rico → aba Timeline com vários tipos
2. Filtrar por Entrevista / Teste / Fit / Avaliação
3. Expandir evento com from/to e motivo
4. CTA abre entrevista e abre score/teste/fit
5. Mover etapa → novo evento `etapa` aparece
6. Adicionar comentário → evento `comentario`
7. Cache bust após deploy local
