# Design: Entrevistas — ciclo de vida completo

Generated by brainstorming on 2026-09-03

## Problem Statement

O protótipo precisa demonstrar o **fluxo completo de agendamento e gerenciamento de entrevistas** para RH, produto/eng e candidato. Hoje existem agenda, formulário parcial e detalhe com poucas ações; faltam modalidade, intervalo início/fim, entrevistadores, máquina de status completa, conflito, reagendamento (RH e pedido do portal), cancelamento com motivo e alerta de entrevista sem resultado após o horário.

## What Makes This Cool

Um fio único: agendar no RH → candidato confirma ou pede reagendamento no portal → detalhe/agenda/dossiê reagem no mesmo objeto → conflito e atraso ficam visíveis sem travar a demo.

## Constraints

- Demo estruturada para o desenvolvimento real (não descartável).
- Audiência: RH + produto/eng + candidatos (portal).
- Front estático: `index.html`, `app.js`, `styles.css`.
- **Sem telas novas de navegação.** Expandir `#interviewDialog`, `#interviewDetailDialog`, página Entrevistas, aba Entrevistas do dossiê e área de entrevistas do portal.
- Sem integração real de calendário/e-mail (toasts demonstrativos).
- Fora desta onda: avaliação formal pós-entrevista, slots auto-livres, sincronização Google/Outlook.

## Decisions (brainstorming)

| Tema | Decisão |
|------|---------|
| Hub | Entrevistas + dossiê + portal (opção C) |
| “Tipo” no formulário | **Modalidade**: Presencial / Videochamada / Telefone (opção A) |
| Natureza RH/Técnica | Via **Etapa** do pipeline (e/ou rótulo derivado da etapa) |
| Status inicial ao agendar | Com “Enviar convite” → Aguardando confirmação; sem → Agendada (opção C) |
| Pedido de reagendamento (portal) | Motivo + mensagem; RH agenda de novo (opção A) |
| Conflito | Mesmo entrevistador **ou** mesmo candidato com overlap; alerta + “Agendar mesmo assim” (opção C) |
| Sem resultado após horário | Status inalterado + badge **Atrasada** (opção B) |
| Abordagem de implementação | Expandir o existente (abordagem 1) |

## Approaches Considered

### Approach 1: Expandir o que já existe

**Escolhida.** Reaproveitar formulário, detalhe, agenda e superfícies do dossiê/portal; evoluir o modelo e as ações.

### Approach 2: Detalhe como painel único de ciclo de vida

Rejeitada nesta onda: mais UI nova; agenda/dossiê ficariam secundários demais.

### Approach 3: Fluxos RH e candidato desacoplados

Rejeitada: duplicação e risco de status divergirem no protótipo.

## Modelo de dados

Cada item em `interviews[]` (fonte única):

| Campo | Tipo / notas |
|-------|----------------|
| `id` | number |
| `candidateId` | number (vínculo estável) |
| `name`, `vacancy` | denormalizados para lista |
| `stage` | etapa do pipeline no momento do agendamento |
| `modality` | `Presencial` \| `Videochamada` \| `Telefone` |
| `at` / `endAt` | ISO local `YYYY-MM-DDTHH:mm:ss` (início/fim) |
| `interviewers` | string[] (nomes; seed com gestores/RH existentes) |
| `location` | string; relevante se Presencial |
| `link` | string; relevante se Videochamada (Telefone opcional) |
| `meet` | derivado de `link` quando aplicável |
| `sheet` | ficha de entrevista (rótulo/template demonstrativo) |
| `notes` | observações internas RH |
| `candidateInstructions` | texto visível ao candidato no portal |
| `status` | ver máquina abaixo |
| `cancelReason` | obrigatório ao cancelar |
| `rescheduleRequest` | `{ reason, message, at } \| null` |
| `inviteSent`, `reminderSent` | boolean |
| `startedAt` | ISO ou vazio; preenchido em “Iniciar” |
| `duration` | minutos (pode derivar de início/fim) |
| `type` | **legado**: mapear para etapa/rótulo; UI nova usa `modality` + `stage` |
| `waiting` | legado; preferir status `Aguardando confirmação` |

**Badge Atrasada (derivada, não é status):**  
Relógio do protótipo (`TODAY_KEY` + hora corrente da demo, ou `endAt` &lt; “agora” seed) **e** status ∈ { Agendada, Aguardando confirmação, Confirmada, Reagendamento solicitado }.

## Máquina de status

Status canônicos:

`Agendada` | `Aguardando confirmação` | `Confirmada` | `Reagendamento solicitado` | `Cancelada` | `Não compareceu` | `Realizada`

### Transições

| Ação | De | Para |
|------|----|------|
| Agendar (sem convite) | — | `Agendada` |
| Agendar (com convite) | — | `Aguardando confirmação` |
| Confirmar manualmente (RH) ou Confirmar (portal) | `Aguardando confirmação` (também `Agendada` se RH confirmar) | `Confirmada` |
| Editar (sem mudar intervalo) | qualquer ativo | mantém status |
| Reagendar (RH) | ativo / `Reagendamento solicitado` | `Agendada` ou `Aguardando confirmação` conforme toggle de convite; limpa `rescheduleRequest` |
| Pedir reagendamento (portal) | `Agendada` \| `Aguardando confirmação` \| `Confirmada` | `Reagendamento solicitado` |
| Cancelar (motivo obrigatório) | ativo | `Cancelada` |
| Registrar não comparecimento | ativo (exceto Cancelada/Realizada) | `Não compareceu` |
| Iniciar entrevista | ativo | mantém status; seta `startedAt` |
| Finalizar entrevista | ativo com ou sem `startedAt` | `Realizada` |

**Ativo** = não está em `Cancelada` | `Não compareceu` | `Realizada`.

## Formulário (criar / editar / reagendar)

Campos:

1. Candidato  
2. Vaga (derivada do candidato; readonly se aberto pelo dossiê)  
3. Etapa  
4. Modalidade: Presencial | Videochamada | Telefone  
5. Data  
6. Horário inicial / final  
7. Entrevistadores (multi-seleção a partir de lista seed)  
8. Local (visível se Presencial)  
9. Link (visível se Videochamada; opcional Telefone)  
10. Ficha de entrevista (select de templates seed)  
11. Observações (RH)  
12. Instruções ao candidato  
13. Toggle Enviar convite (define status inicial / pós-reagendamento)

Validação mínima:

- Início &lt; fim  
- Presencial ⇒ local obrigatório  
- Videochamada ⇒ link obrigatório  
- Ao menos um entrevistador  
- Conflito: se overlap com mesmo entrevistador **ou** mesmo candidato em entrevista ativa → dialog de alerta com **Voltar** / **Agendar mesmo assim**

Modos do mesmo dialog: `create` | `edit` | `reschedule` (título e CTA mudam; reagendar exige novo intervalo).

## Superfícies

### Página Entrevistas (agenda + lista)

- Cards/lista mostram modalidade, intervalo, status, badge Atrasada quando couber.
- Abrir detalhe no `#interviewDetailDialog`.
- Filtros existentes passam a reconhecer os novos status (mapear legado `Concluída` → `Realizada` nos seeds).

### Detalhe RH

Ações (habilitadas conforme status):

| Ação | Comportamento |
|------|----------------|
| Editar | abre formulário em modo edit |
| Reagendar | modo reschedule |
| Cancelar | motivo obrigatório → `Cancelada` |
| Confirmar manualmente | → `Confirmada` |
| Copiar link | clipboard + toast |
| Enviar convite | `inviteSent = true`; se status era `Agendada` → `Aguardando confirmação`; toast |
| Enviar lembrete | `reminderSent = true`; toast |
| Registrar não comparecimento | → `Não compareceu` |
| Iniciar entrevista | seta `startedAt` |
| Finalizar entrevista | nota opcional → `Realizada` |

Cada ação registra no `history` / `activities` do candidato vinculado.

### Dossiê do candidato

- Aba Entrevistas: **Próximas** = status ativos (Agendada, Aguardando confirmação, Confirmada, Reagendamento solicitado); **Encerradas** = Realizada, Não compareceu, Cancelada. Badge Atrasada pode aparecer dentro de Próximas.
- “Agendar entrevista” usa o formulário completo.
- Clique no item abre o mesmo detalhe RH.

### Portal do candidato

- Card da entrevista: status, data/hora, modalidade, local ou link, instruções.
- Se `Aguardando confirmação`: botão **Confirmar**.
- Se ativo (não cancelado/realizado/no-show): **Pedir reagendamento** → motivo + mensagem → `Reagendamento solicitado`.
- Sem editar horário diretamente.

## Sincronização

- Fonte única: `interviews[]`.
- Agenda, detalhe, dossiê e portal leem o mesmo registro (`candidateId` + `id`).
- Após qualquer mutação: `renderAgenda` + refresh do detalhe se aberto + `renderCandidateDetails` se dossiê aberto + refresh da view portal de entrevistas.

## Seeds / roteiro de demo

1. **Conflito:** tentar agendar overlap no mesmo entrevistador (ou candidato) → alerta → forçar.  
2. **Cancelamento:** cancelar com motivo → status Cancelada visível na agenda e portal.  
3. **Reagendamento RH:** mudar horário de uma Confirmada → novo status conforme convite.  
4. **Pedido do candidato:** no portal, pedir reagendamento → RH vê `Reagendamento solicitado` e reagenda.  
5. **Atrasada:** seed com `endAt` no passado e status Confirmada → badge Atrasada sem mudar status.
