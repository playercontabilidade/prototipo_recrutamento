## Problem Statement

O protótipo precisa de um ciclo completo de **Fit Cultural**: perfil cultural da empresa, banco de perguntas, modelos aplicáveis a vagas, envio ao candidato, acompanhamento de status e análise de aderência (geral, por pilar, fortes/divergências, esperado × candidato), incluindo **comparar candidatos** e **reaproveitar resultado válido**.

Hoje existe apenas um stub no dossiê: score `%` manual (`candidate.fitCultural`) e pilares inventados a partir desse número. Não há configuração tipada, modelos, envios nem resultado estruturado.

## Scope

### In

- Nav **Fit Cultural** em Seleção (entre Testes e Fichas)
- Página `#fitCulturalPage` com 4 abas e contagens
- **Perfil**: CRUD de pilares (nome, descrição, peso %, importância); soma de pesos = 100% (aviso visual)
- **Banco**: CRUD de perguntas (pergunta, pilar, tipo, alternativas, pontuação, peso, obrigatória)
- **Modelos**: criar, duplicar, editar; nome; perguntas do banco + ordem; pesos; vagas vinculadas; validade (dias)
- **Aplicados**: lista de envios com status, % aderência, resultado por pilar; abrir detalhe
- Ações: Aplicar · Reenviar · Copiar link · Visualizar respostas · Visualizar resultado · Comparar candidatos · Reaproveitar resultado válido · Cancelar (quando couber)
- Modal de detalhe (padrão Testes): meta + abas Respostas / Resultado; footer enxuto (primária + Copiar link + Mais ações) sem duplicar abas
- Resultado: aderência geral; por pilar; pontos fortes; divergências; perfil esperado × candidato
- Comparar: 2–3 candidatos mesma vaga/modelo → tabela lado a lado
- Reaproveitar: se existir resultado anterior do mesmo modelo/candidato dentro da validade, oferecer reuso em vez de novo envio
- Dossiê: aba Fit Cultural consume assignment real
- Portal: candidato responde Fit (mock) e avança status até Concluído com aderência calculada
- Seeds: ~4 pilares, ~8 perguntas, 1–2 modelos, alguns envios em status variados
- Cache bump

### Out

- Motor psicométrico real / calibração IRT
- Multi-avaliador ou revisão humana de Likert
- Backend / persistência real
- Misturar Fit Cultural no catálogo de Testes (técnico/comportamental/competências)

## Surfaces

1. **Nav** — `data-page="fit-cultural"` → `#fitCulturalPage`
2. **Perfil / Banco / Modelos / Aplicados** — painéis por aba na mesma página
3. **Modal detalhe** — `#fitAssignmentDetailDialog`
4. **Modal comparar** — `#fitCompareDialog`
5. **Dossiê** — `#candidateFitContent` (e CTA Aplicar)
6. **Portal candidato** — fluxo de resposta do Fit

## Data model

```text
culturalProfile:
  pillars[]: { id, name, description, weightPct, importance }  // importance: alta|media|baixa

fitQuestions[]:
  id, prompt, pillarId, type  // likert | single | multiple
  options[]: { id, label, score }
  weight, required, active

fitModels[]:
  id, name, questionIds[] (ordem), questionWeights?: { [questionId]: number }
  vacancyTitles[] | jobIds[]
  validityDays, active

fitAssignments[]:
  id, candidateId, vacancy, jobId?, modelId
  sentAt, dueAt, status  // Não iniciado | Em andamento | Concluído | Expirado | Cancelado
  link, answers[]: { questionId, value }
  adherencePct: number | null
  pillarScores[]: { pillarId, pct }
  strengths[]: string
  gaps[]: string
  reusedFromId?: number | null
  completedAt?: string | null
  cancelledAt?: string | null
```

- Aderência geral = média ponderada pelos pesos dos pilares (a partir das respostas × pontuação das alternativas × peso da pergunta).
- No protótipo, cálculo determinístico mockado a partir das respostas seed/portal.

## Status machine

```text
Aplicar → Não iniciado
Portal abre → Em andamento
Portal conclui / RH marca → Concluído (calcula aderência + pilares + fortes/gaps)
Prazo vencido sem conclusão → Expirado
Cancelar → Cancelado
Reenviar → Não iniciado (novo link / prazo)
Reaproveitar → Concluído (copia scores do assignment válido; marca reusedFromId)
```

## UI notes

- Contagens: Banco, Modelos, Aplicados (ativos/não cancelados); Perfil pode mostrar nº de pilares
- Modal: não incluir no menu “Visualizar respostas/resultado” se já existem abas
- Comparar: seleção multipla na lista Aplicados ou no dossiê da vaga; mínimo 2
- Reaproveitar: só quando houver assignment Concluído do mesmo `modelId` + `candidateId` com `completedAt` dentro de `validityDays`

## Error / empty states

- Perfil sem pilares → bloquear criar modelo / aplicar
- Banco vazio → bloquear modelo sem perguntas
- Aplicados vazio → empty state + CTA aplicar pelo dossiê
- Comparar com <2 selecionados → toast

## Testing (manual)

1. Nav Fit Cultural → 4 abas com seeds
2. Editar pilar/peso; criar pergunta; duplicar modelo
3. Aplicar no dossiê → aparece em Aplicados (Não iniciado)
4. Portal responde → Em andamento → Concluído com % e pilares
5. Modal: respostas + resultado (fortes/divergências/esperado × candidato)
6. Comparar 2 candidatos
7. Reaproveitar resultado válido em nova aplicação da mesma validade
8. Stub antigo de “digitar Fit %” não é mais o caminho principal
