# Design: Condução de entrevista ao vivo

Generated by brainstorming on 2026-09-03  
Repo: Prototipação Vagas (local)  
Status: APPROVED  
Mode: Builder  
Approach: A — modal única de condução

## Problem Statement

O recrutador precisa de uma tela prática **enquanto conversa** com o candidato: percorrer a ficha vinculada, registrar respostas, anotar e finalizar com parecer — sem misturar isso com o catálogo de Fichas nem com a agenda.

Hoje `#interviewDetailDialog` só faz `start` / `complete` (flags de status). O preenchimento da ficha estava fora de escopo da onda de Fichas.

## Decisions

| Tema | Decisão |
|------|--------|
| Hub / entrada | Detalhe da entrevista: **Iniciar** / **Continuar** → condução |
| Superfície | Modal ampla `#interviewConductDialog` (não página fullscreen, não item de nav) |
| Fonte das perguntas | Ficha vinculada (`sheetId` → `interviewSheetTemplates`) |
| Abordagem | Modal única: condução + passo de finalização interno |
| Escopo | MVP “completo o bastante” (ver Scope) |

## Scope

### In

- Modal ampla de condução ligada a `start` / rascunho existente
- Header: candidato, vaga, etapa, horário, entrevistadores, ficha; atalhos Currículo e histórico resumido
- Centro: pergunta atual, resposta (por tipo da ficha), prev/next, obrigatória, progresso, autosave
- Lateral: abrir currículo + anotações da entrevista
- Rodapé: salvar rascunho + finalizar
- Finalização na mesma modal: nota, parecer, recomendação (Avançar / Reprovar / Banco de Talentos / Avaliar posteriormente), próxima etapa
- Protótipos: saída acidental, recuperação de rascunho, obrigatórias pendentes, confirmação de finalização
- Persistência demo em `interview.conductDraft` (+ efeitos de status/desfecho no protótipo)
- Cache bump

### Out

- Item novo no menu Seleção
- Painel rico de tags / avaliações anteriores / dados detalhados da vaga (reusar dossiê)
- Pontos positivo / atenção estruturados como entidade
- Multi-entrevistador editando ao mesmo tempo
- Export PDF / sync real com análise do gestor
- Reinventar catálogo `#fichasPage` ou preview ilustrativo

## Surfaces

1. `#interviewDetailDialog` — CTAs Iniciar / Continuar / Finalizar (quando aplicável)
2. `#interviewConductDialog` — workspace (header + Q&A + lateral + rodapé)
3. Passo / overlay interno de finalização + dialogs de confirmação (sair / finalizar / pendentes)
4. Reuso: `openCandidateResume()`, dados do candidato/entrevista existentes

## Data model

```text
interview.conductDraft?:
  sheetId: number
  currentQuestionId: number | null
  answers: { questionId, value, updatedAt }[]
  notes: string
  score?: number | null          // preenchido na finalização
  opinion?: string
  recommendation?: "advance" | "reject" | "talent_bank" | "evaluate_later"
  nextStage?: string
  updatedAt: ISO string
  finalizedAt?: ISO string | null
```

- Autosave: ao mudar resposta/notas, atualiza `conductDraft.updatedAt` + toast discreto / label “Salvo automaticamente”.
- `start` define `startedAt` se ainda vazio e abre condução.
- Finalizar com sucesso: `status = "Realizada"`, aplica recomendação no protótipo (ex. estágio, banco, dispensa mock), limpa ou marca `finalizedAt`.

## Layout (condução)

| Zona | Conteúdo |
|------|----------|
| Header | Meta da entrevista + Currículo + Histórico resumido |
| Centro | Progresso · pergunta · controle de resposta · Anterior / Próxima |
| Lateral | Currículo (CTA) · Anotações |
| Rodapé | Salvar rascunho · Finalizar entrevista |

## Fluxos prototipados

| Fluxo | Comportamento |
|-------|----------------|
| Saída acidental | X / Esc / fechar com draft dirty → confirma “Sair sem concluir?” |
| Recuperação | Detalhe com draft → **Continuar entrevista**; restaura pergunta e respostas |
| Obrigatórias pendentes | Finalizar com required vazias → bloqueia e lista pendentes (pode ir à pergunta) |
| Confirmação de finalização | Segundo passo: nota + parecer + recomendação + próxima etapa → confirmar |

## Integração com ciclo de vida

- Substitui o `complete` “seco” (só `Realizada`) pelo wizard quando a entrevista tem ficha / condução.
- Sem ficha vinculada: toast pedindo ficha ou fallback mínimo (só parecer) — preferir **exigir ficha ativa** no protótipo se `sheetId` ausente após normalize.
- Agenda / portal do candidato: sem mudança além do status pós-finalização.
